## 一、30 秒版

> "事务 = 把多条写捆绑成一个不可分割的单元，用 **ACID** 四个属性定义：原子性(全做或全不做)、一致性(约束始终成立)、隔离性(并发互不干扰)、持久性(提交后不丢)。**并发**产生三类问题——脏读/不可重复读/幻读，用四级隔离级别压(读未提交→读已提交→可重复读→串行化)，MySQL 默认可重复读，靠 **MVCC + 锁**实现。但重点：DB 事务只保证**库内**一致，Agent 链路里真正难的是**外部副作用**(已调的 API、已发的消息、Checkpoint 落盘)DB 事务回滚不到——那部分只能靠**幂等 + 补偿(附录A2)** 和 **最终一致(第23/24课 MQ)**。"

## 二、完整答题卡

### 2.1 ACID 是什么

| 特性 | 含义 | 通俗理解 |
|---|---|---|
| 原子性 Atomicity | 事务内操作不可分割 | "全做或全不做"，无中间态 |
| 一致性 Consistency | 事务前后都满足约束 | 转账前后总额不变 |
| 隔离性 Isolation | 并发事务互不干扰 | 看不到别人的中间态 |
| 持久性 Durability | 提交后永久保存 | 断电/崩溃也不丢 |

一句话：**一致性是目的，原子/隔离/持久是达成它的手段**（A/I/D 是为 C 服务的）。

### 2.2 并发问题与隔离级别

| 问题 | 描述 | 解决它的隔离级别 |
|---|---|---|
| **脏读** | 读到别人**未提交**的数据，他回滚了我就白读 | >= READ COMMITTED |
| **不可重复读** | 同一条记录两次读取值不同 | >= REPEATABLE READ |
| **幻读** | 两次查询**行数**不同(插入/删除) | = SERIALIZABLE |

四级隔离从弱到强：`READ UNCOMMITTED` → `READ COMMITTED` → `REPEATABLE READ` → `SERIALIZABLE`
- MySQL InnoDB 默认 **REPEATABLE READ**（靠 MVCC 已能基本规避幻读）。
- 隔离更强 = 并发更弱，选型是吞吐 vs 一致性的权衡。

### 2.3 底层机理（背完能讲"为什么"）

- **原子性** → `undo log`：记录变更前镜像，失败时按日志反向回滚。
- **持久性** → `redo log`：先写 redo 再落盘（WAL），崩溃后用 redo 恢复，最小化 fsync 次数。
- **隔离性** → `锁 + MVCC`：MVCC 多版本并发控制，读走 **快照读**(历史版本)、写走 **当前读**(加锁)，读写互不阻塞。通过版本号 + 隐藏列(trx_id/roll_pointer)实现。
- **串行化** → 加锁，或间隙锁(Gap Lock)防幻读。

### 2.4 事务使用原则

- **事务要短**：持有锁时间长会阻塞别的写事务。
- **别在事务里做外部 IO**：调 API、发消息、大循环——外部副作用 DB 管不到，还会把锁拖很久。
- **先快失败**：尽早校验，别让错误数据进入事务。

## 五、追问 Q&A

**Q1：事务的原子性靠什么保证？**
A：`undo log`。事务未提交前先写变更前镜像，失败时按 undo log 反向回滚到原始状态。

**Q2：MySQL 默认隔离级别是什么？为什么用它可以避免幻读但又不是串行化？**
A：REPEATABLE READ。靠 MVCC 的**快照读**让同一事务内多次查询看到同一快照，配合 `Next-Key Lock`(记录锁+间隙锁)锁住范围防插入，所以基本规避幻读；但仍保持读不加锁的高并发，不像 SERIALIZABLE 全部加锁。

**Q3：数据库事务能保证"调用外部 API + 更新数据库"整体成功吗？**
A：不能。DB 事务只能保证库内原子性，外部 API 的副作用它管不到也无法回滚。正确做法：先落库再发副作用、副作用配**幂等 key**、失败用**对账/补偿**(Saga)收敛 —— 即附录A2那套。

**Q4：Redis 的 MULTI/EXEC 算是事务吗？**
A：算是"命令打包顺序执行"，但它**不支持回滚**、也管不到并发隔离，所以不是严格的 ACID 事务。并发正确性靠 WATCH + 乐观锁。

**Q5：跨服务多事务怎么保持一致？**
A：几条路：**2PC** 强一致但锁死周期长、**TCC** 业务补偿、**本地消息表 + MQ 最终一致**(第23/24课)。无绝对最优，按对一致性的要求选。

## 六、避坑

- 别把 DB 事务当万能：它在**分布式 Agent 链路里管不到外部副作用**，这是这题最高的分水岭。
- 隔离级别别只背名字，要讲"选它解决了哪个问题 / 我线上用了哪个为什么"。
- MVCC 别只抛名词，说清 `undo log`、快照读 vs 当前读、隐藏列。
- 别把"本地消息表"(最终一致)和"DB 事务"(强一致)混为一谈，是两个层次。
