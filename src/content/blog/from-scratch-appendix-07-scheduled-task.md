## 一、30 秒版

> "定时任务按运行形态分五类：**进程内**调度(setTimeout/node-cron,单机轻量,进程挂了就丢)；**系统级**(crontab/systemd,不占业务进程,耦合弱)；**调度框架/平台**(XXL-Job/ElasticJob/DolphinScheduler,自带执行器+重试+分片,生产主流)；**延时消息**(Redis zset/MQ 延时消息,契合异步链路,常见于我们的 Agent 任务队列)；**云托管**(K8s CronJob/EventBridge/函数计算)。选型的三个命门：**单机够不够**、**多实例会不会重复执行(要分布式锁)**、**错过/失败的要不要补偿**。无论哪种，**执行端必须幂等**(附录A2)。"

## 二、完整答题卡

### 2.1 五类实现

| 层级 | 代表 | 适用 | 缺陷 |
|---|---|---|---|
| 进程内 | Node `setTimeout`/`node-cron`、Python `APScheduler`、Java `@Scheduled` | 单机轻量/心跳/缓存刷新 | 进程挂=任务丢；多实例重复执行 |
| 系统级 | Linux `crontab`/`systemd`、macOS `launchd`、Windows 任务计划 | 定期跑脚本/备份 | 与业务耦合弱、可观测性差 |
| 调度平台 | XXL-Job、ElasticJob、DolphinScheduler、Airflow | 多实例/需重试/分片/DAG 编排 | 引入中间件，重 |
| 延时消息 | Redis `zset+轮询`、RabbitMQ `TTL+死信`、RocketMQ 定时消息 | 异步链路、到期投递 | 需自管 ack/去重 |
| 云托管 | K8s CronJob、AWS EventBridge、函数计算定时触发 | 免运维、随业务弹性 | 平台锁定 |

### 2.2 三种触发语义（先分清楚再选实现）

| 语义 | 含义 | 典型实现 |
|---|---|---|
| **cron(到点)** | 每天/每周固定时刻触发一次 | crontab、node-cron、XXL-Job |
| **interval(周期)** | 每隔固定间隔循环 | setInterval、@Scheduled |
| **delay(延时)** | 投递到"未来某时刻"执行一次 | Redis zset、MQ 延时消息 |

> 区分：**周期**和**延时**是两回事——"3 秒后执行"用延时队列，不是 crontab。

### 2.3 多实例正确性（面试真正考的点）

```
怎么触发不重要，触发了怎么不重复执行、挂了怎么补，才是要害
```

1. **防重复执行**：多实例 + 调度平台时，同一任务只能一个 worker 跑 → **分布式锁**(Redis `SETNX`/ReentrantLock)。
2. **执行端幂等**：即使锁失效/重试，任务本体也要幂等(附录A2)，避免"扣了两次钱"。
3. **错过补偿**：进程崩溃/机器宕机错过的任务，靠**任务表 `next_run_at` 扫描 + 补偿脚本**补上，而不是放任不跑。
4. **失败重试**：瞬时错误指数退避(第32课)，永久错误告警 + 人工介入。

### 2.4 延时任务在 Agent 场景的落地

Agent 的任务队列(第23/24课)天然就是"延时/异步"：
- **到期投递**：任务 → Broker 延时队列 → Worker 到期消费。
- **进度/状态**：用 Redis Hash 存 `running/completed/failed`(第26课)。
- **分布式锁**：多 Worker 抢同一个任务时为避免重复处理，加 Redis 锁。

## 五、追问 Q&A

**Q1：定时任务在分布式下怎么保证不重复执行？**
A：靠**分布式锁**抢占——Redis `SETNX` 设锁，成功者执行，失败者跳过；并给锁加过期时间防止持锁实例崩溃死锁。锁之上执行端还要**幂等**双保险。

**Q2：进程重启，错过的定时任务还跑吗？**
A：进程内的定时器重启即丢；生产要落**持久任务表**(记录 `next_run_at`)，重启后扫描没跑的任务补偿执行。

**Q3：cron、interval、delay 有什么区别？**
A：cron 是"到固定时刻触发"(每天 3 点)，interval 是"固定间隔循环"(每 5 分钟)，delay 是"投递到未来某时刻执行一次"(3 秒后)。三者的实现与选型完全不同。

**Q4：Redis 做延时任务可靠吗？跟 MQ 比呢？**
A：Redis 简单、低延迟(第24课)，适合轻量；但**不保证消息不丢**、无 ack。真正要可靠投递用 MQ 延时消息(RabbitMQ TTL+RocketMQ 定时)，配 ack + 重投。

## 六、避坑

- 别只报"crontab / XXL-Job"枚举，重点讲**多实例防重复**和**错过补偿**。
- 别把"延时任务"和"周期任务"混一起说，先分语义再选实现。
- 别漏**执行端幂等**——分布式锁只是第一层,锁也会失效,幂等才是兜底。
