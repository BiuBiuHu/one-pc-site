Loop Engineering —— AI Agent が自分で書き、テストし、出荷する全自動開発フロー —— に銀の弾丸はない。巨大な「完全自律」ループを追うのは間違いだ。半年の落とし穴のあと、結論はこうなった。**正しいやり方は、垂直シナリオごとに1セットの Skills。核は spec + TDD**。この記事は、どう落地したかの話。

去年の11月から、Coding Agent と密集してコードを書いてきた。ずっと完全自律を追っていた。今ふうに言えば Loop Engineering だ。

## 核の考え方：/goal + Skills

Skills は Loop Engineering の最良の器だ。垂直シナリオごとに自分の Loop Engineering を持つべきで、何でも屋の巨大 Loop Engineering を1つ持ってはいけない。

用語を先に置く。

- **Skills**：Agent 向けの能力パック。1つの垂直シナリオにスコープする（ある種の仕事の進め方を拘束する）
- **spec**：要件仕様
- **TDD**：テスト駆動開発。実装の前にテストケースを書く

良い Loop Engineering は2部品からなる。`/goal` + Skills。Skills の中でいちばん大事なのは spec + TDD —— 要件ごとに spec をはっきり書き、テストケースもはっきり書く。

## Skills が開発プロセスを拘束する

各 goal を落地するとき、Skills は生産フローを拘束しなければならない。

1. 要件の見極め
2. 技術設計の分析
3. タスク分解
4. 実装
5. ユニットテストの完成
6. テスト受け入れ

## TDD が開発品質を拘束する

### テスト能力の先埋め

既存リポジトリなら、新しいブランチを切り、ユニットテストを一度に埋め、トランクへ戻す。後続ブランチが影響を受けない。

### 品質保証を並行する

技術設計の段階で影響分析をする。テスト計画の段階でユニットテスト分析と結合テスト分析をする。成果物はユニットテスト文書、スモークケース、フルケース。

コードを書いたあと、Agent は各種ケースを書き始め、デプロイ前に自己テストへ入る。テストケースが厚いと、品質は相対的に安定し、手戻りが減る。

### トークン消費を抑える

大きなテストスイートは人手を解放するが、トークンも爆発する。解は2つ。

1. **テスト範囲の分析**：今回の変更が触るものだけをテストする。毎回フルセットを走らせない
2. **結合テストのフレームワーク**：フレームワークにテストを走らせ、Agent は結果だけを取る。AI にケースを1本ずつ実行させない

品質側をこう組み直すと、出るコードはほぼそのまま使え、テストコストも下がる。

## 出荷をループに入れる

Loop Engineering である以上、出荷もループの一部でなければならない。私は Vercel を DevOps 役にしている。preprod / production の環境ロジックと vercel-cli を Skills に入れた。コードが終わるたびに自動デプロイされ、かなりの時間を節約している。
